# Page: sro_checker

Overrides `MASTER.md` for the local auditor tool.

## Composition

- Not a marketing landing. First viewport = **upload + run**.
- Dense operator layout: summary strip → tabs → table.
- Brand mark «СРО-Аудитор» is visible but does not dominate the workflow.

## Atmosphere

- Blueprint grid on cool slate background.
- Safety-orange primary CTA only for «Проверить».
- Risk as stamp/pill (КРИТИЧНО / РУЧНАЯ / НОРМА), not emoji.

## Motion

- Stagger fade-up for header, upload, results (~40ms steps).
- Button hover 180ms; respect `prefers-reduced-motion`.

## a11y

- Visible `:focus-visible` rings.
- File inputs labelled; buttons have clear names.
- Table headers sticky; numeric columns tabular-nums.

---

## Composition variants (wireframes)

Recommended default: **A — Stack desk**. Keep B/C as optional if density or dual-pane becomes a real need.

### A — Stack desk (рекомендуемый)

Линейный поток сверху вниз. Максимум сканируемости, минимум решений «куда смотреть».

```
┌─────────────────────────────────────────────────────────┐
│ [mark] СРО-Аудитор              локально · без сервера  │
│        проверка ВВ / ОДО                                │
├──────────────────────────┬──────────────────────────────┤
│  Файл 1 · члены СРО      │  Файл 2 · договоры / ОДО     │
│  [ drop / выбрать ]      │  [ drop / выбрать ]          │
├──────────────────────────┴──────────────────────────────┤
│  [ Демо ]              [ Проверить ] ← orange CTA       │
├─────────────────────────────────────────────────────────┤
│  Всего N │ Критично n │ Ручная n │ Норма n │ [CSV]     │  ← summary strip
├─────────────────────────────────────────────────────────┤
│  [ Все ] [ Критично ] [ Ручная ] [ Норма ]              │  ← tabs
├─────────────────────────────────────────────────────────┤
│  ИНН │ Член │ ВВ │ ОДО │ Δ │ Штамп                      │
│  …   │ …    │ …  │ …   │ … │ КРИТИЧНО                   │  ← sticky thead
│  …   │ …    │ …  │ …   │ … │ НОРМА                      │
└─────────────────────────────────────────────────────────┘
```

**Когда:** текущий MVP и основной рабочий день.  
**Плюс:** один взгляд, мобильная укладка естественная.  
**Минус:** на ультрашироком экране таблица «растягивается» — ок.

### B — Rail + stage

Слева узкая рельса управления, справа сцена результатов. Ближе к IDE / CAD.

```
┌──────────────┬──────────────────────────────────────────┐
│ СРО-Аудитор  │  Сводка: N / крит / ручн / норма  [CSV] │
│              ├──────────────────────────────────────────┤
│ Файл 1       │  [ Все | Критично | Ручная | Норма ]     │
│ [ drop ]     ├──────────────────────────────────────────┤
│ Файл 2       │  таблица результатов (sticky)            │
│ [ drop ]     │                                          │
│              │                                          │
│ [Демо]       │                                          │
│ [Проверить]  │                                          │
└──────────────┴──────────────────────────────────────────┘
```

**Когда:** оператор держит файлы постоянно «под рукой» и гоняет несколько прогонов подряд.  
**Плюс:** controls не уезжают при длинной таблице.  
**Минус:** на ≤768px рельса обязана стать stack (как A); сложнее a11y focus order.

### C — Summary-first desk

Сначала полоса рисков (даже до детальной таблицы), upload компактнее.

```
┌─────────────────────────────────────────────────────────┐
│ СРО-Аудитор · ВВ/ОДО          [Демо] [Файлы▾] [Проверить]│
├─────────────────────────────────────────────────────────┤
│ ┌ Критично n ┐ ┌ Ручная n ┐ ┌ Норма n ┐ ┌ Членов N ┐   │  ← крупные счётчики
├─────────────────────────────────────────────────────────┤
│ фильтры-табы + поиск по ИНН                             │
├─────────────────────────────────────────────────────────┤
│ таблица (основной фокус)                                │
└─────────────────────────────────────────────────────────┘
```

Файлы спрятаны в компактный «Файлы▾» / drawer после первого успешного прогона.

**Когда:** повторные сессии на уже знакомых выгрузках; акцент на triage рисков.  
**Плюс:** быстрее «есть ли пожар?».  
**Минус:** первый визит менее очевиден (upload вторичен) — хуже для онбординга.

## Decision

| Критерий | A Stack | B Rail | C Summary-first |
|---|---|---|---|
| Time-to-first-check | ★★★ | ★★ | ★ |
| Скан рисков | ★★ | ★★ | ★★★ |
| Мобильный | ★★★ | ★ | ★★ |
| Соответствие текущему HTML | ★★★ | ★ | ★★ |

**Ship A.** Рассматривать B только если появятся частые повторные прогоны без перезагрузки страницы; C — если основной сценарий станет triage уже посчитанного отчёта.
