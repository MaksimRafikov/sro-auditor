# Словарь колонок и нормализация

GPT и HTML-чекер должны распознавать колонки по смыслу, а не только по точному названию.

Подбор колонки: сначала точное совпадение нормализованного имени, затем `includes` с приоритетом более «короткого» заголовка относительно алиаса (чтобы «контрагент» не цеплял «…обязательствах контрагента»). Короткие алиасы (&lt; 4 символов) — только exact.

## Реестр членов СРО

| Смысл поля | Типичные названия |
|---|---|
| ИНН | ИНН, inn, ИНН контрагента |
| Название | Контрагент, Наименование, Организация, Член СРО, Сокращенное наименование |
| Статус членства | Статус, Статус членства |
| Состояние права | Состояние права, Право, Статус права |
| Уровень ВВ | Уровень ВВ, Лимит ВВ, Уровень ответственности ВВ |
| Уровень ОДО | Уровень ОДО, Лимит ОДО, Уровень ответственности ОДО (не путать с флагом права «ОДО») |
| Расчёт обязательств | Расчёт обязательств, Расчет обязательств, Расчет размера обязательств |
| Дата расчёта | Дата расчёта размера обязательств |
| Дата начала приостановки | Дата приостановления, Приостановлено с, Дата приостановки |
| Дата окончания приостановки | Дата возобновления, Приостановлено по, Возобновлено |
| Признаки права | КС, ОО, ОДО, АЭ |

## Реестр договоров

| Смысл поля | Типичные названия |
|---|---|
| ИНН участника | ИНН, ИНН подрядчика, ИНН участника, ИНН поставщика |
| Название | Член СРО (поставщик), Член СРО, Подрядчик, Контрагент, Участник |
| Стоимость к учёту СРО | Стоимость, принятая СРО к учету / учёту; **Стоимость работ по договору** (выгрузки ЕИССЗ/1С) |
| Стоимость исполненных работ | **Сумма принятых работ по договору**, Стоимость принятых работ, Принятых работ, Исполнено, Принято |
| Вид / способ закупки | Вид закупки, Способ закупки, Тип закупки, Закон |
| Признак ОДО | Договор ОДО, Признак ОДО |
| Номер договора | Номер договора, № договора (не «Номер договора в ЕИС») |
| Дата договора | **Дата заключения договора**, Дата заключения, Дата договора (не «Дата договора в ЕИС») |
| Исключить из обязательств | **Не учитывать договор в обязательствах контрагента**, Не учитывать договор |

## Нормализация ИНН

1. Привести к строке.
2. Убрать пробелы, точки, дефисы.
3. Для юрлиц — 10 цифр, для ИП — 12.
4. Сопоставлять строго по нормализованному ИНН.

## Нормализация сумм

1. Убрать пробелы-разделители тысяч.
2. Заменить запятую на точку при необходимости.
3. Привести к числу в рублях.
4. Если сумма в млн/тыс. указана текстом — пересчитать и пометить «ручная проверка».

## Формула остатка по договору

```text
Остаток = Стоимость к учёту − Сумма/стоимость принятых работ
```

Если колонка исполнения не найдена — остаток = полная стоимость, статус не ниже «ручная проверка», в UI — предупреждение.

Если флаг «Не учитывать договор в обязательствах» = да — договор не входит в max ВВ и в сумму ОДО.

## Нормализация уровня ВВ/ОДО в числовой лимит

Примеры текста → лимит:

| Текст | Лимит, ₽ |
|---|---:|
| до 90 млн | 90_000_000 |
| до 500 млн | 500_000_000 |
| до 3 млрд | 3_000_000_000 |
| до 10 млрд | 10_000_000_000 |
| свыше 10 млрд / 10 млрд и более | Infinity |
| отсутствует / не указано / пусто | null |

## Нормализация состояния права

| Текст | Значение |
|---|---|
| действует / активен / да | действует |
| приостановлено / приостановлен | приостановлено |
| исключён / прекращено | прекращено |

## Нормализация конкурентности договора

Конкурентный = true, если в поле способа закупки / закона есть:
`44`, `223`, `615`, `конкурс`, `аукцион`, `тендер`, `закупк`, `торг`

Или если есть явный признак ОДО = да/true/1.
